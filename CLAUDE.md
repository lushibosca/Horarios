# Directivas del proyecto

- Después de cada cambio en el código, estilos o HTML, ejecutar `npm run release` (sube `APP_VERSION` y `CACHE_NAME` del Service Worker para invalidar la caché) y luego `npm run typecheck` y `npm test`. El workflow de GitHub (`.github/workflows/tests.yml`) corre también `npm run typecheck`, y ahí fallaron errores de tipos que `npm test` no detecta.
- Si `npm run typecheck` y `npm test` pasan sin errores, hacer commit automáticamente (sin esperar a que se pida) con un mensaje descriptivo en español, incluyendo `sw.js` con la versión nueva. No hacer push.
- Los modales (y cualquier contenedor) cuyo contenido cambie de largo estando abiertos (listas que se recalculan, secciones que se muestran u ocultan) deben animar el cambio de alto: envolver el cambio en `Animaciones._animarAlturaCambio(elemento, mutarFn)` (usa `--dur-collapse` y respeta "reducir animaciones"). Nada de saltos de tamaño.
- Los controles en fila (chips, `.day-checkbox`, botones) no pueden solaparse: al agregar uno nuevo, revisar su estado marcado/hover (el `scale(1.1)` de `.day-checkbox` solo sirve con muchos elementos angostos; con pocos usar `.week-selector--opciones`) y verificarlo en ancho de celular antes de dar el cambio por terminado.
- Las animaciones nuevas deben usar solo `transform` y `opacity` (van al compositor y no repintan). Nada de animar `background-position`, `box-shadow`, `outline`, `filter`, `width`/`height` o `top`/`left`; si hace falta un efecto de luz, borde o aro, usar una capa temporal (elemento o pseudo-elemento) que se mueve o se escala. La excepción es el alto de contenedores (`Animaciones._animarAlturaCambio`).
